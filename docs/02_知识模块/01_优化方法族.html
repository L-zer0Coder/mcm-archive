MMCM/ICM 备赛知识库 02_知识模块

优化方法族（LP · MILP · 启发式）

学习核心模块之一，服务的典型场景：资源分配、选址、排产、调度、搜索规划。 验证环境：SciPy 1.18 / NumPy 2.5.1 / PuLP 2.7.0 / CBC，Windows，2026-11-22 全部代码实跑通过。 赛制相关的内容（题型映射、比赛规则）在 03_题型打法，本模块只讲方法本身。

0. 先建地图：三种境界

境界 变量 求解器 一句话适用 验证方式
LP 线性规划 连续 scipy.optimize.linprog（HiGHS） 流量、配比、运输——比例可切分 影子价格、对偶
MILP 混合整数 整数+连续 scipy.optimize.milp（HiGHS）、PuLP+CBC 选/不选、台数、指派——离散决策 gap 界、与松弛对照
启发式 任意 自己写（贪心/局部搜索/遗传） 求解器超时、目标非凸非线 必须与界或精确解对照

心法三句：先把问题写成"变量–目标–约束"三行表再动手；能精确就精确、超时才降级；启发式的价值要用界来证明，不是用运行时间来证明。

1. 概念讲透

1.1 三要素：把题面翻译成数学

任何优化问题都只由三样东西构成。以运输问题为例——3 个产地供给 $(30,50,20)$，3 个销地需求 $(25,35,40)$，单位运价矩阵 $c_{ij}$：

$$\min \sum_{i=1}^{3}\sum_{j=1}^{3} c_{ij}x_{ij} \qquad \text{s.t.}\quad \sum_j x_{ij}=s_i,\ \sum_i x_{ij}=d_j,\ x_{ij}\ge 0$$

符号表（读到新符号回来查）：

符号 含义 单位
$i,\ j$ 产地 / 销地的编号 —
$s_i,\ d_j$ 产地 $i$ 的供给量 / 销地 $j$ 的需求量 吨
$c_{ij}$ 从 $i$ 运到 $j$ 的单位运价 元/吨
$x_{ij}$ 决策变量：从 $i$ 运到 $j$ 的量 吨

翻译检查法：每个决策问一句"你要决定什么"（变量）、"你在优化什么"（目标）、"什么不能违反"（约束）。经验法则：题面里的名词（运量、台数、时刻）是候选变量，动词与要求（不超过、必须在…之前）是候选约束，"最大化/最小化/最…"是目标。三行写不出来，说明题还没读懂，不要开写代码。

这个模型悄悄用了三条假设，写论文时要显式说出来：线性（总运费是各段运量之和，没有联合折扣）、比例可分（运 0.7 吨也可以，LP 才成立）、数据确定（$s,d,c$ 已知且不随机）。

1.2 先判断：这个问题该用优化吗

不是所有问题都轮得到优化出场。三问自查：有没有可控行动（只能预测趋势的问题去统计模块）；不确定性的主角是谁（随机主导的问题去蒙特卡洛模块）；有没有明确决策变量（说不清"决定什么"就先别建优化模型）。优化回答的是"给定情景，最好的行动是什么"，它不负责预测情景本身。

1.3 LP 的几何与对偶：敏感度分析的理论来源

LP 可行域是凸多面体。若最优解存在，必有一个顶点达到最优（最优解集合也可能是一整条边甚至一个面——§2.3 演示的正是这种情况；无界可行域则可能没有最优解）。单纯形法就是沿顶点搜索的算法。

更重要的是对偶：每个约束都对应一个影子价格（shadow price），它回答"某资源多一个单位，目标值变多少"。注意这个解读对不等式约束直接成立（约束松紧由你控制）；对等式约束，"多一个单位资源"必须两侧同时调整才有意义，读数时要小心（§2.1 有一手示例）。

这是 LP 比启发式高一个境界的原因：求解器不只给你最优方案，还给你敏感度全貌。非绑定约束的影子价格为 0；绑定约束的影子价格告诉你放宽哪条约束最划算。报告敏感度分析，LP 直接引用求解器输出的对偶值即可，这是最省力且最有说服力的写法。

1.4 整数为什么难：分支定界、松弛与 gap

要求某些变量取整数后，问题从多项式可解变成 NP-hard。主流求解器用分支定界：不断解 LP 松弛（允许分数取值），松弛值是整数最优的界（min 问题它是下界，max 问题它是上界）；某个变量的分数解 $\bar x$ 处分成 $x \le \lfloor\bar x\rfloor$ 与 $x \ge \lceil\bar x\rceil$ 两支继续搜，用界剪掉不可能超过已知最优解的分支。

由此得到本模块最重要的一个工具——gap（最优性间隙）：

$$\text{gap} = \frac{|z_{IP} - z_{LP}|}{|z_{IP}|} \times 100\%$$

其中 $z_{IP}$ 是整数最优（或当前最好整数解）、$z_{LP}$ 是松弛解目标值。min 问题里 $z_{IP} \ge z_{LP}$，分子就是"整数解减下界"；max 问题反过来。gap 是证明"解接近最优"最标准的凭证（小规模精确解对照、已知基准实例也是合法凭证），求解器终止时会自动给出（res.mip_gap），也可用参数控制杀到多小（常用 1%）。

big-M 陷阱：MILP 里"要么…要么…"约束常用大常数 $M$（如 $x \le M \cdot y$）。$M$ 取得过大，松弛变得毫无区分度，求解慢到天荒地老；取得过小会误杀最优解。$M$ 要从数据算出来，例如 $M = \text{系数} \times \text{变量上界} + \varepsilon$（即该变量物理上可能的最大值再留一点余量），不要无脑取 1e6。

1.5 启发式的定位：它是妥协，不是替代

启发式（贪心、局部搜索、遗传算法）不保证最优，它的价值在两个场景：求解器确实超时；目标函数非凸非线性、根本写不成 LP。写启发式必须回答两个问题：解可行吗（逐条检查约束）、离最优多远（拿界或小规模精确解对照）。答不了第二个问题的启发式，说服力只有一半。

2. 最小可复现代码

以下代码 2026-11-22 在 SciPy 1.18 / NumPy 2.5.1 / PuLP 2.7.0 / CBC 实跑通过，输出为真实运行结果。离线环境准备见 §4.7。

2.1 LP：运输问题（linprog，HiGHS 内嵌免安装）

from scipy.optimize import linprog
c = [4, 6, 9, 5, 3, 8, 8, 5, 4]            # 单位运价 c_ij，按行展开
A_eq, b_eq = [], []
for i, s in enumerate([30, 50, 20]):       # 供给约束
    r = [0] * 9
    for j in range(3): r[i * 3 + j] = 1
    A_eq.append(r); b_eq.append(s)
for j, d in enumerate([25, 35, 40]):       # 需求约束
    r = [0] * 9
    for i in range(3): r[i * 3 + j] = 1
    A_eq.append(r); b_eq.append(d)
res = linprog(c, A_eq=A_eq, b_eq=b_eq, bounds=(0, None), method="highs")
print("最小总运费 =", round(res.fun, 1))
plan = {(i, j): float(round(res.x[i*3+j], 1)) for i in range(3) for j in range(3)
        if res.x[i*3+j] > 1e-9}
print("运输方案 =", plan)
print("影子价格 =", [round(float(m), 1) + 0.0 for m in res.eqlin.marginals])

真实输出：

最小总运费 = 450.0
运输方案 = {(0, 0): 25.0, (0, 2): 5.0, (1, 1): 35.0, (1, 2): 15.0, (2, 2): 20.0}
影子价格 = [4.0, 3.0, -1.0, 0.0, 0.0, 5.0]

三处读法：

  • 方案：产地 2 的 20 吨全给了销地 2（运价 4 最便宜），销地 2 的需求 40 由三方凑齐——LP 在替你做全局权衡。这个 LP 解恰好全是整数不是巧合：供需都是等式的运输问题系数矩阵是全单模的，LP 解天然整数。这也解释了 §0 里"流量配比可用 LP"的深层原因；反过来，一旦约束混入不等式或非网络结构，LP 解就可能出现分数。
  • 影子价格：六个数对应六条约束（前三条供给、后三条需求）。注意本例是等式约束，这组数要当成"对偶位势"来读（检验 $c_{ij}$ 与位势之和的关系），不能直接读成"销地 2 多一吨需求省 5 元"——等式约束下两侧要一起动，"多一单位资源"的直接解读只对不等式约束成立（§1.3）。若把供给写成 $\le s_i$（用 A_ub/b_ub），边际值就是标准的"放宽一单位约束能省多少运费"。
  • 运行时间：res 里有 res.nit（迭代次数）与求解耗时，报告时一并给出。

2.2 MILP：背包问题（milp）+ LP 松弛对照

import numpy as np
from scipy.optimize import milp, LinearConstraint, Bounds
v = np.array([60, 100, 120, 40, 70], float)   # 价值
w = np.array([10, 20, 30, 10, 24], float)     # 重量
con = LinearConstraint(w, -np.inf, 50)        # 容量 50
ip = milp(c=-v, constraints=[con], integrality=np.ones(5), bounds=Bounds(0, 1))
lp = milp(c=-v, constraints=[con], bounds=Bounds(0, 1))   # 松弛：去掉 integrality
print("整数最优 =", int(-ip.fun), "选中 =", np.where(ip.x > 0.5)[0].tolist())
print("LP 上界 =", round(-lp.fun, 2), "松弛解 =", np.round(lp.x, 3).tolist())
print("求解器 mip_gap =", ip.mip_gap)
print("gap = (上界-整数最优)/整数最优 =",
      round((-lp.fun + ip.fun) / -ip.fun * 100, 1), "%")

真实输出：

整数最优 = 220 选中 = [1, 2]
LP 上界 = 240.0 松弛解 = [1.0, 1.0, 0.333, 1.0, 0.0]
求解器 mip_gap = 0.0
gap = (上界-整数最优)/整数最优 = 9.1 %

读法：松弛解允许"拿 1/3 个物品 2"（价值 240），整数解拿不到分数，只能退而求 220。上界 240 告诉你任何算法都不可能超过 240。两个 gap 要分清：求解器自己报的 mip_gap = 0.0 是说"分支定界已证明这个解就是整数最优"；手算的 9.1% 是拿最终整数解对初始 LP 界的差距，回答的是"如果只允许用启发式级别的解法，离最优最多差多少"。报告时用哪个，取决于你想证明"已最优"还是"近似得够好"。

2.3 建模层：PuLP 同一背包（语法可读，求解器可换）

import pulp   # 注意：pip install pulp==2.7.0（见 §4.6 版本纪律）
vals = [60, 100, 120, 40, 70]
wts = [10, 20, 30, 10, 24]
p = pulp.LpProblem("knapsack", pulp.LpMaximize)
x = [pulp.LpVariable("x{}".format(i), cat="Binary") for i in range(5)]
p += pulp.lpSum(vals[i] * x[i] for i in range(5))
p += pulp.lpSum(wts[i] * x[i] for i in range(5)) <= 50
p.solve(pulp.PULP_CBC_CMD(msg=False))
print("状态 =", pulp.LpStatus[p.status], " 价值 =", int(pulp.value(p.objective)),
      " 选中 =", [i for i in range(5) if x[i].value() > 0.5])

真实输出：

状态 = Optimal  价值 = 220  选中 = [0, 2, 3]

对比 §2.2：目标值同为 220，但 CBC 选了另一组物品 [0,2,3]（60+120+40，重量恰 50），HiGHS 选 [1,2]（100+120，重量 50）。 这个例子真实演示了多重最优解：最优值唯一，最优方案未必唯一。读论文和写论文都要盯目标值与约束余量，不要迷信"求解器选的方案就是唯一答案"——这正是 §1.3 说"最优解集合可能是一整条边"的实例。

2.4 贪心启发式 + 与最优对照

import numpy as np
v = np.array([60, 100, 120, 40, 70], float)
w = np.array([10, 20, 30, 10, 24], float)
order = sorted(range(5), key=lambda i: -v[i] / w[i])   # 性价比降序
cap, got, val_sum, chosen = 50, 0.0, 0, []
for i in order:
    if got + w[i] <= cap:
        got += w[i]; chosen.append(i); val_sum += v[i]
print("性价比排序 =", order)
print("贪心选中 =", chosen, " 价值 =", val_sum, " 重量 =", got)
print("与整数最优差 =", 220 - val_sum, "（{}%）".format(round((220 - val_sum) / 220 * 100, 1)))

真实输出：

性价比排序 = [0, 1, 2, 3, 4]
贪心选中 = [0, 1, 3]  价值 = 200.0  重量 = 40.0
与整数最优差 = 20.0 （9.1%）

贪心卡在 200（重量只用 40，浪费了 10 吨容量），最优 220。这个 9.1% 就是启发式必须付出、也必须报告的代价。改进方向：从贪心解出发做局部搜索（交换/替换一个物品），通常能把差距压到 1–2%。

3. 在真题中的用法

以下题目信息核查于 2026-11-22（来源：COMAP 官网历年题目页）。方法族如何落地，比题目本身更重要——每道题都能先做"三行翻译"。

真题 场景 优化范式 三行翻译
2024 MCM B《Searching for Submersibles》（潜水器搜救） 失联观光潜水器（末段位置与航速已知）的搜救规划 搜索努力分配：网格化海域，把有限搜索资源分给各网格，最大化累计探测概率 变量=各网格搜索时长/次数；目标=$\max\sum(\text{探测概率})$；约束=总预算、平台续航
2025 MCM B《Managing Sustainable Tourism》（可持续旅游） 景区承载量下的游客管理 容量约束下的流量规划与调度 变量=各时段/景点流量；目标=体验或收益最大化；约束=生态承载力、季节波动
2026 MCM B《Creating a Moon Colony Using a Space Elevator System》（太空电梯月球殖民） 地月货运与建设排程 货运调度/物流网络：批次、窗口、装载 变量=各批次运量与时刻；目标=建设进度或成本；约束=发射窗口、运力、依赖序

其中 2024 B 是"搜索努力分配"范式的标准案例，该场景的标准工具组合是贝叶斯搜索理论 + 网格化努力分配 + 蒙特卡洛模拟（语料库建成后在此补充对应卡片链接）。它与本模块 §2.2 的背包是类比关系：都是"预算换收益"，但探测概率对搜索努力是边际递减的凹函数，严格建模要用可分凹资源分配或分段线性化——背包只覆盖"选/不选"的离散版本，别把类比当成同构。

网络与运筹类场景（最短路径、网络流、调度）是本方法族的主场：前两者是 LP/MILP 的特例，排队系统本身的演化是随机过程（属蒙特卡洛/仿真模块），但排队系统的优化决策（如服务台配置）常回到 MILP。用到时先回忆 §0 的地图，问一句"这题的连续部分和整数部分分别是什么"。

4. 常见误用

  1. 黑箱求解不查可行性。模型报 infeasible 就摊手，是新手最常见的死法。排查三步：把约束逐条打印成区间表、找互相打架的两条；检查单位（吨 vs 千克、小时 vs 分钟）；检查 big-M 是否把可行域压死。永远先让一个"显然可行"的测试解过一遍约束，再谈优化。
  2. 0-1 变量对称性爆炸。给 20 个相同设备指派任务、设备之间可互换，分支定界会把每种排列都搜一遍。破对称：加字典序约束 $y_1 \ge y_2 \ge \cdots$，或把"设备"改写成"第 k 个启用的设备"。
  3. big-M 无脑取 1e6。见 §1.4——$M$ 必须从数据上界算出（$M = \text{系数} \times \text{变量上界} + \varepsilon$），否则松弛无区分度、数值报警。
  4. 把启发式结果当最优宣称。启发式结果不得裸报，必须附界证据。写法模板："greedy 达到 200，位于 LP 上界 240 与精确解 220 之间，达到最优的 90.9%，可接受"。
  5. 敏感度分析只做"改一个参数重跑十次"。LP 直接引用影子价格（§1.3）；MILP 做参数扫描时报告趋势与拐点，而不是贴十张表。
  6. 不锁版本。PuLP 4.x 用 Rust 重写了核心 API：LpVariable(cat=...) 等全网教程写法直接报错，CBC 不再捆绑、PULP_CBC_CMD 也已移除（本站 2026-11-22 在 PuLP 4.3.1 实测，不要走"只改 cat 写法"的修复路径）。工作环境提前冻结：pip freeze > requirements.txt，论文附录注明版本号。
  7. 现场才装求解器。现场网络不可赌，提前离线轮子准备（在有网机器执行下载；目标机的 Python 版本与操作系统平台必须与下载机一致，否则轮子装不上）：

pip download -d ./wheels scipy pulp==2.7.0 numpy --only-binary=:all:

目标机离线安装：

pip install --no-index --find-links ./wheels scipy pulp==2.7.0 numpy

  1. 目标函数无量纲意识。把"成本（元）"和"时间（小时）"加进同一个目标必出灾难。除了加权前归一化，还有两种标准做法：ε-约束（保留主目标，其余目标写成约束并给容差 ε）与字典序（按优先级逐层求解，先定成本上限再优化时间）。权重或 ε 的选择本身要做敏感度分析。

5. 自检清单

  • 先过了 §1.2 三问：有行动、不确定性不是主角、变量说得清
  • 三行翻译（变量/目标/约束）先于代码存在，符号表齐
  • 模型假设显式（线性/可分/数据确定——或写明为什么违反仍可接受）
  • 变量类型表：哪些连续、哪些整数、为什么
  • 求解器输出三件事都报告：最优值、gap、运行时间
  • LP 有影子价格表（等式约束按位势解读）；MILP 有与松弛的 gap 对照
  • 启发式有界参照（LP 上界或小规模精确解）
  • 敏感度分析不是"重跑十次"，而是影子价格/趋势拐点
  • 环境锁定（requirements.txt + 版本号进附录）
